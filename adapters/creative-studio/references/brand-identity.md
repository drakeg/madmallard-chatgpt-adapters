# Distinctive product branding and first-class image generation

## Trigger and authority

Apply to **new independent products, unbranded launches and explicitly authorized rebrands**. For ordinary bug fixes, approved identities and small updates, **preserve** the existing brand. Creative Studio owns coordination; Taste owns personality, palette, typography and page composition; image generation creates original visual directions; Owl verifies usability and accessibility; MengTo implements; Algorithmic Art creates procedural imagery if beneficial; Scroll Craft is reserved for immersive brand storytelling.

## Research first, without a lengthy questionnaire

Read the existing product repository, assets and brand standards. Reuse known target audience, purpose, personality, customer problem and desired conversion action. Ask 1–3 **only consequential** unanswered questions. Use the user's answers, or choose reasonable style options if delegated. A color preference is not normally an authorization blocker; a request to discard an approved brand is consequential.

## Anti-repetition decision rule

Independent products deserve **distinct identities**, not a renamed template. For each new identity, compare against available recent product designs across these dimensions: (1) hue and contrast scheme, (2) typography and letterform character, (3) symbol/visual metaphor, (4) illustration/photo treatment, (5) composition and site/page grammar, (6) motion and interaction language. If a direction is substantially similar on several axes, revise it before presenting. Do not simply recolor a generic initials logo or copy the same dark gradient and card grid. Explicitly document when reuse is justified by shared branding, user direction or an existing design system.

## Visual identity candidates

When no approved logo exists, generate **three genuinely different logo concepts** with an available image-generation capability, each with a unique concept, mark structure, type direction, and intended personality. Examples of differences: geometric emblem vs. character/illustrative mark vs. expressive custom wordmark (not mandated categories). Display actual outputs when created; otherwise provide clearly labeled design specifications and never imply an image was produced. Briefly state the audience fit, visual uniqueness, monochrome/miniature legibility and trade-offs.

Offer a **meaningful creative choice** at new-brand establishment. Request selection or let the user explicitly delegate the choice. Do not call an unreviewed mark approved. Once approved, do not repeatedly ask for routine design sign-off on every iteration.

## Color, type, composition and imagery

- Select a fresh palette from the product's positioning, audience and accessibility needs; include named semantic roles and contrast-tested pairings. Never default to one recurring palette.
- Choose appropriate, legally usable fonts with fallback stacks; retain a typography scale and adequate readable measure.
- Pick site structure from the actual visitor journey rather than a universal SaaS dashboard/landing template. Different businesses may need different hierarchy, navigation, density and icon approaches.
- Generate original illustrations, textures, product-support visuals, backgrounds and imagery when they increase comprehension, recognition or perceived quality; avoid unnecessary decorative image generation.
- Keep recognizable brand differentiation without impairing conversions or usability.

## Asset repository contract

In the **individual product repository**, prefer a documented brand root such as `brand/` or `assets/brand/`, plus `docs/BRAND.md`. Record approved decisions, hex/semantic palette, typeface licenses/fallbacks, logo concepts/selection, original source/prompts, rights, actual output files and accessibility notes. Store optimized transparent logo and light/dark/monochrome variants (SVG if truly editable, raster otherwise), appropriate favicons and reusable imagery; add correctly sized metadata icons and existing component theme tokens. Do not fabricate vectors from raster output or embed fonts without suitable rights. Ensure no secrets or private customer data are committed.

## Tests and evidence

- Test applicable WCAG AA color contrast (normally 4.5:1 for regular text, 3:1 for large text; meaningful non-text UI 3:1), responsive reflow and readable type.
- Test keyboard navigation, focus indicator, reduced motion, target sizes, logo/favicon visibility and image variants at representative viewport widths.
- Check license/attribution, broken assets, large file sizes, and current identity preservation.
- Report **generated vs. proposed**, **tested vs. unchecked**, **approved vs. selected by delegation** distinctly. Actual runtime checks require available tools and access; a written checklist is not a passed test.
- Run Build → Test → Refine → Deploy using available authorized infrastructure. Do not make deployment claims without verification.

## Cases

- Brand-new product with no logo: three visually different generated logo options if a generation tool is connected, then one decision and persist assets.
- Unrelated projects: no automatic reuse of prior palette/logo/font/layout.
- Existing approved brand: maintain current approved choices and improve within that system; no mandatory logo generation.
- User says "Surprise me": autonomous design selection, with transparent provenance; never invent formal approval.
- No image generation: three usable text specifications, status marked unrendered; no fake asset files.
- Maintenance fix: no brand exercise, just repair.
